## Corrections importantes déjà réalisées

### Sessions candidat/recruteur

Le token JWT était initialement stocké dans `localStorage`.

Cela provoquait un problème lorsque deux comptes étaient ouverts dans le même navigateur : le recruteur pouvait remplacer le token du candidat, ce qui faisait apparaître le même `senderId`.

Correction :

- utilisation de `sessionStorage` ;
- session isolée par onglet ;
- Axios et Socket.IO utilisent le token de l’onglet courant ;
- suppression de l’ancien token localStorage lors de la déconnexion.

Fichier concerné :

```text
frontend/src/services/authStorage.js
```

### Conversations

Le bouton “Ouvrir la conversation” naviguait uniquement vers `/messages` sans créer ni retrouver précisément la conversation.

Nouvelle route backend :

```text
POST /api/conversations/matches/:matchId
```

Cette route :

- vérifie que le match est accepté ;
- vérifie que l’utilisateur est participant ;
- crée la conversation si nécessaire ;
- retourne la conversation existante si elle existe déjà ;
- évite les doublons.

Les boutons candidat et recruteur ouvrent maintenant la bonne conversation avec son `conversationId`.

### Messages temps réel

Les messages HTTP étaient enregistrés en base mais pas diffusés via Socket.IO.

Correction :

- après un envoi HTTP, le backend émet `message:new` dans la room ;
- le message contient l’expéditeur peuplé ;
- les messages reçus sont actualisés automatiquement sans rechargement.

### Distinction des messages

Chaque message contient :

```text
senderId
senderRole
conversationId
```

Le frontend utilise `senderId` en priorité pour déterminer si le message appartient à l’utilisateur connecté.

La vue affiche également :

- “Vous” pour les messages envoyés ;
- “Candidat” ou “Recruteur” pour les messages reçus ;
- alignement gauche/droite ;
- couleurs différentes ;
- heure du message.

### Synchronisation des conversations

La page messages :

- vide les anciens messages lorsqu’une autre conversation est sélectionnée ;
- ignore les réponses réseau obsolètes ;
- déduplique les messages HTTP et Socket.IO ;
- compare les `conversationId` après normalisation ;
- utilise des mises à jour React fonctionnelles.

### Notifications

Corrections réalisées :

- fusion sécurisée entre chargement REST et événements Socket.IO ;
- les notifications reçues en temps réel ne sont plus écrasées par la requête initiale ;
- compteur non lu temps réel candidat et recruteur ;
- marquage individuel comme lu ;
- marquage global comme lu ;
- accès notifications dans les deux dashboards.
